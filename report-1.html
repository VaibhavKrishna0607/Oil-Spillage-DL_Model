From image patches to defensible spill intelligence.

A practical readiness report for turning the current SOS PNG dataset into a reproducible segmentation baseline, then connecting it to georeferenced drift hindcasting and historical vessel attribution.

Updated 25 August 2026 · review incorporated

Executive verdict

Verified in repository

Good starting material

8,070 paired 256×256 PNG samples are present across train and val directories. The repository includes a PyTorch dataset, joint augmentations, deterministic split lists, a U-Net, hybrid BCE+Dice loss, and PyTorch/TorchScript/ONNX checkpoint files.

Critical before demo claim

Current report overstates readiness

The PNG patches do not contain latitude/longitude transforms. Pixel polygons cannot honestly be drawn on a real map yet. The current plan also lacks drift hindcasting/forecasting, historical or synthetic AIS, geometric properties, and multi-factor attribution.

Core decision: treat the existing PNGs as a training baseline, not as geospatial evidence. Build the pipeline so every training run has a manifest, fixed splits, measurable metrics, and a clear handoff to a separate georeferenced demo dataset.

The new data foundation

Run the data gate before every split or training run:

python data_pipeline/build_manifest.py --root .
python data_pipeline/sanity_check.py --root .
python data_pipeline/prepare_splits.py --root .

Manifest, not guesswork

build_manifest.py writes artifacts/dataset_manifest.csv and artifacts/dataset_audit.txt. Each row records pair status, dimensions, sensor, oil fraction, mask bounding box, and SHA-256 hashes.

  • Reject missing, unreadable, non-finite, or mismatched pairs.
  • Review empty masks as intentional negatives, never silently discard them.
  • Use hashes to detect duplicates and source changes.

Split for generalization

For the current patch dataset, keep the supplied lists for reproducibility but label their provenance honestly. For full scenes, add a scene_id and split by scene/acquisition, not by neighboring patch filename.

  • Keep test untouched until final evaluation.
  • Report per-sensor metrics: PALSAR and Sentinel-1.
  • Report positive/negative sample counts and mask-size bins.
Training contract: a run is valid only when the manifest hash, split-list hash, seed, image normalization, augmentation settings, model configuration, and checkpoint metric are saved beside the checkpoint.

Execution order

Days 1–2 · lock the baseline

  • Run the manifest and inspect audit outputs.
  • Correct split provenance in documentation.
  • Train a baseline and record IoU, Dice/F1, precision, recall, and per-sensor results.
  • Freeze a model/data version for comparison.

Days 3–6 · make the demo truthful

  • Acquire georeferenced scenes and verify transforms.
  • Implement geometry extraction and tiled inference.
  • Build drift hindcast/forecast with deterministic synthetic weather fallback.
  • Generate/query synthetic historical AIS and expose factorized scoring.

Days 7–10 · integrate and rehearse

  • Connect FastAPI JSON contracts to the map/report.
  • Show uncertainty bands and provenance in the UI.
  • Test offline using frozen data; keep live AIS as a future monitoring adapter.
  • Record a complete backup demo and challenge every claim in the slides.
Honest project position: the segmentation baseline is a credible start. The PS-aligned product is not complete until georeferencing, drift reconstruction, historical/synthetic AIS correlation, and structured geometric evidence are implemented and tested.
